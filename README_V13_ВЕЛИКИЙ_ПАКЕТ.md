# AGRO BAROMETER V13 — великий пакет для однієї майбутньої публікації

**Дата складання: 25.10.2026.** Ця збірка створена локально з попередньої V13 STAGING (на базі V12.1), а не з поточної гілки GitHub. На сайті зараз підтверджена опублікована V12. Жодних автоматичних віддалених змін не виконано.

## Головне
- У цьому ZIP **усі файли повного Netlify-сайту**: `public/`, `netlify/functions/`, `scripts/`, `package.json`, `netlify.toml`.
- Містить зміни V12.1, які користувач іще не публікував, і нову V13.
- Новий блок V13 підключений до публічних ендпойнтів і показує розподіл по 6 культурах, причини відсутності економічних доказів, звіт про транспортну базу та список оголошень для перевірки.
- Новий Netlify endpoint `/.netlify/functions/logistics-place` за наявності `GRAPHHOPPER_API_KEY` намагається підтвердити точну адресу пункту приймання та повернути автомобільну відстань. **Це не вантажний маршрут** і не тариф. При неоднозначності адреси — жодних кілометрів.
- V13 показує публічні цифри оголошень лише з позначкою **«одиниця невідома»**. Не приписує автоматично грн/т, ПДВ, базис, клас чи юридично підтверджену ставку.
- Економічний двигун підтримує самовивіз та продавцеву доставку, уніфікацію ПДВ, групи культур/якості/умов оплати, строгу валідацію доказів.
- Двигун **не підставляє** право на податковий кредит без підтвердження. Не змішує різні ставки ПДВ або договори.
- Відсутні перевірені транспортні ставки = відсутній доведений економічний рейтинг; пропозиції не оголошуються економічно невигідними.
- 11 барометрів, вихідні збирачі, V11.1 адмін-токен і дані у Netlify Blobs не видаляли й не перезаписувалися.

## Список обмежень (важливо)
1. Немає автоматичного імпорту дозволених тарифів DELLA / DeGruz / Transportica; дозволи / офіційні API мають бути підтверджені. Парсинг приватних груп не підключений.
2. Реальні дані V11 не мають документованого робочого процесу підтвердження (`validated_for_market_model=false` при створенні). Публічний API не віддає деякі поля V13; тому **поточна база не може породити рейтинг**, навіть за наявності оголошень.
3. GraphHopper використовує `car`, що не підтверджує законність проїзду зерновоза 25 т. Для автоматичної логістичної рекомендації потрібна окрема верифікація вантажного маршруту / транспортна котировка до конкретного місця.
4. Відсутні підтверджені клас/якість, ПДВ, базис і правило перерахунку для публічних цін. Це свідомо блокує доведений рейтинг.
5. Не реалізовано приватну базу покупців — за домовленістю.
6. Візуальний тест у реальному браузері та інтеграційний тест із робочим Netlify не проводилися — зокрема через відсутність секретного GraphHopper-ключа в локальному середовищі.

## Перевірки
`npm test` — **86 успішних тестів**, 0 помилок; також виконується перевірка синтаксису JavaScript.

## Як публікувати одним кроком, коли вирішимо
1. Зробити резервну копію GitHub гілки `main` (або позначити попередній commit для rollback).
2. Розпакувати ZIP і завантажити **вміст** папки, а не папку-обгортку, у корінь GitHub репозиторію.
3. Упевнитися, що `netlify.toml` лишився в корені, `public/index.html` лежить у `public`, функції — у `netlify/functions`.
4. Дочекатися успішного Netlify deploy і перевірити головну сторінку, блоки V12/V12.1/V13 та GET `freight-rates`.
5. Перевірити, що старі 11 барометрів не змінилися; POST із неправильним токеном має залишатися 401.
6. `GRAPHHOPPER_API_KEY` не потрібно записувати у файли: за бажанням додати як environment variable у Netlify і зробити redeploy.
7. Якщо після публікації виявиться регресія, у Netlify повернути попередній успішний deploy або відкотити GitHub commit.
