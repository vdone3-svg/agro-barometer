# AGRO BAROMETER Auto V6.2 — єдиний фільтр якості

## Проблема
Минулі версії повертали старий знімок `public-indicators-latest` без повторної перевірки, хоча `offer-history` фільтрував архів. На сайті зберігалися пошкоджені пункти приймання.

## Зміни
- `public-indicators` фільтрує збережені оферти **під час кожного читання**, тож після deploy не потрібно запускати збір вручну.
- Нові знімки також проходять цей самий серверний фільтр перед записом.
- `crop_coverage` перераховується лише за видимими кандидатами, а `quality_control` показує `source_candidates`, `published_candidates`, `hidden_malformed`.
- Сайт має додаткову перевірку очевидного змішування назви компанії / наступного товару.
- `offer-history` і надалі приховує проблемні архівні записи, **не видаляючи** їх із Netlify Blobs.
- Барометри 0–100 не змінюються.

## Встановлення
Розпакувати ZIP; завантажити *вміст* архіву в корінь наявного GitHub-репозиторію, замінивши файли; `Commit changes` у `main`. Перевірити успішний Deploy Netlify. Відкрити `/.netlify/functions/public-indicators` і переконатися, що поле `quality_filter_version` дорівнює `unified_v62`, а `quality_control` присутнє в `grain.data`. Перевірити головну сторінку. **Run now не потрібний** для усунення дефектів із уже збереженого знімка.

Це фільтр явної текстової контамінації, а не перевірка точності ціни, одиниць виміру, ПДВ чи базису. Сумнівні, але неявні помилки все ще можливі. Не використовуйте дані для автоматичного рейтингу покупців.
